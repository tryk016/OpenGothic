# iOS shader startup profile

This port keeps the upstream Tempest Metal renderer. It does not import the
unfinished `RendererIOS` experiment. Cold startup is shortened at three safe
boundaries, all of which preserve the normal runtime compiler as a fallback.

## Startup sequence

1. `Shaders::compileKeyShaders()` creates only the Bink and save-thumbnail
   pipelines synchronously.
2. The remaining catalogue compiles on the existing worker future. The first
   menu and swapchain resize do not wait for that future on iOS.
3. Entering or replacing a world still calls `Shaders::waitCompiler()`. A
   compiler exception is propagated there instead of reaching the renderer as
   an empty pipeline.

The iOS catalogue omits groups which cannot be used by the selected startup
configuration: VSM, RTSM, GI, software ray tracing and CMAA2. CMAA2 builds only
the selected preset. Release builds also omit diagnostic ray-query shaders.
Desktop builds retain the upstream full catalogue.

## Precompiled startup Metal libraries

The iOS build creates separate libraries for `triangle.vert` and
`downscale.frag`. A library contains one `main0` function, matching Tempest's
runtime entry point exactly. Separate device and simulator builds contain Metal
2.4, 3.0 and 3.1 variants, so the application can select the same language
version that Tempest will use on the current OS.

Canonical MSL is generated by a small native build tool compiled from Tempest's
vendored SPIRV-Cross sources. The generator uses Tempest's iOS options, including
the flipped vertex Y axis, buffer-size slot 29 and disabled read/write texture
fences. It also compares the two extreme argument-buffer and image-alignment
profiles byte for byte. The build stops rather than packaging a shader if those
device capabilities change its canonical MSL.

Before constructing `MetalApi`, the iOS application reads the matching
metallib and canonical MSL from its signed bundle. It derives the current Metal
profile, computes Tempest's full source/profile key and supplies the library via
`MetalApi::Options::precompiledLibraries`. Full SHA-256 values generated at
build time are compiled into the application; a missing, modified or malformed
resource is rejected before Metal sees it.

The assets remain optional. If the native generator or Metal tools are missing,
the current profile is unknown, a hash or source/profile key differs, or Metal
rejects a library, Tempest follows its normal SPIR-V -> canonical MSL ->
`newLibrary` path. Repeated runtime modules are still covered by the configured
shader-module cache.

Bink deliberately stays on the runtime path. It is not needed for the initial
screen, and its unsized SSBO arrays depend on Tempest's runtime buffer-length
metadata and resource layout. The precompiled set therefore remains limited to
the two startup shaders whose capability-independent output is verified by the
build.

No writable runtime `MTLBinaryArchive` is used. A read-only archive can be
added later only after it is captured and validated on representative devices;
it is an optional pipeline-state optimization, not a replacement for the
shader-library fallback.

## Compatibility and verification

- Deployment target remains iOS 15.0, including iOS 16.4.
- The generator emits matching iPhoneOS or iPhoneSimulator targets for Metal
  2.4, 3.0 and 3.1 and uses no optional GPU feature in these two shaders.
- Verify symbols with `metal-nm`; all six libraries must contain exactly one
  function named `main0`.
- A release build must contain six `OpenGothic*.metallib` files and their six
  canonical `OpenGothic*.mslsrc` files in the application bundle.
- Verify the six generated expected hashes independently against the packaged
  metallib bytes.
- Device acceptance covers a fresh install, warm relaunch, intro playback,
  first world load and saving a thumbnail.
